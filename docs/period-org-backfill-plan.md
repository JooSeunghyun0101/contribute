# 연도별 부서·상위조직 반영 계획 (Option B)

> 작성일 2026-06-17 · 상태: **적용 완료(2026-06-17)** — 마이그레이션·백필(1689건)·프런트 그룹핑 전환 반영. 검증: 연결회계팀 본부 25=회계본부/26=AX회계본부, 직원33 2025 정상 제외.
> 목적: 평가 화면의 부서 그룹핑을 **그 평가 기간의 실제 부서·상위조직** 기준으로 정확화.

---

## 1. 배경 / 문제

- 현재 부서 그룹핑은 `employee.org_*`(= **현재/2026 스냅샷**) 기준.
- 그래서 **25년을 조회해도 전보자가 26년 부서로 묶임.**
  - 예: 직원33 — 26년 연결회계팀이 **25년 화면에도** 노출(실제 25년은 리스크관리팀).
  - H071 연결회계팀 본부도 25 `회계본부` → 26 `AX회계본부`로 달라, 연도별 스냅샷이 실제로 필요.
- 해결(**Option B**): **각 평가(evaluation) 행에 그 기간의 부서코드·법인/본부/부/팀을 저장**하고, 화면 그룹핑을 평가 기준으로 전환.

## 2. 확정 전제 (사용자 결정)

- **88명**(기여도 있으나 종합마스터 부재)은 **최종 기여도평가 대상 아님 → 제외 유지.**
  - 직원33 25년 미조회는 **정상**(3~9월 휴직·종합마스터 부재). 원인 규명 완료.
- **로스터 불변** → 신규 평가 삽입 없음 → **기존 평가에 org만 채우는 in-place 백필**(파괴적 재적재 아님).

## 3. 데이터 소스 (검증 완료)

| 연도 | 부서코드 출처 | 상위계층 출처 | 해상도 |
|---|---|---|---|
| 2025 | `2025_발령이력부서id추출.xlsx`(평가자 기준) + 폴백 `25년 종합평가 결과.xlsx` 부서코드 | `조직_251101.xlsx` | 마스터 1266 → **100%** |
| 2026 | `26년 기여도_260610.xlsx` 부서코드(소속별) | `조직_260617.xlsx` | 199 코드 → **100%** |

- 발령이력: 사번 100% 커버. `소속순번`은 기여도 `소속`과 **무관**(직접 조인 불가).
- **연결고리 = 평가자**: 평가자 = 팀 조직장(조직파일 col7 = 조직장 사번). 예: O044 리스크관리팀 조직장 9000028 = 직원34 ✓.

## 4. 2025 평가별 부서 배정 규칙

각 평가(피평가자 X, 평가자 E)에 대해 우선순위:

1. **X의 발령부서 중 조직장 == E** → 채택 *(일반 팀원, 평가별 정확)*
2. **단일 활성(비휴직) 발령부서** → 채택
3. **종합마스터의 X 부서코드** → 채택 *(팀장/모호 케이스의 100% 해상 폴백)*
4. 그 외 → **미지정**

- 비운영 부서(`휴직자소속` 등 이름에 `휴직|대기발령`) 제외.
- 조직_251101 미존재 4개(`BX팀`·`마케팅본부/기획부/기획팀`)는 260617 또는 미지정 폴백(소수).
- 다중평가 133명 중 51명은 ①로, 나머지(팀장 본인)는 ③ 마스터 부서로 안정 귀속.

## 5. 2026 평가별 부서 배정

- 평가 행을 `(피평가자 사번, 평가자 사번)` 으로 26 기여도에 매칭 → 그 행의 부서코드 → 조직_260617.
- 전보 2건(예: 직원33 리스크관리팀/연결회계팀)도 소속별로 정확.

## 6. 조직 계층 매핑 (법인/본부/부/팀)

- 조직파일 = T-Level 들여쓰기 트리(row2~, col1=부서명·col2=T-Level·col3=부서ID·col10=조직종류·col7=조직장사번).
- 부서ID의 **자기+조상 체인**에서 조직종류로 4단계 추출:
  - **법인** = `대표`(T2) → 약어(`fill_org_hierarchy.cjs` CORP_ABBR 재사용: OKV/EX/OKH/OK/OC/ACI/AFI/YA/OKAX/OKIP)
  - **본부** = `본부` 노드(없으면 `-`)
  - **부** = `부` 노드(없으면 `-`)
  - **팀** = `팀`/`지점` 리프(= 부서 노드 자신, 부/본부 직속이면 `-`)

## 7. 스키마 변경

`evaluations`에 컬럼 추가(전부 nullable, 백필):

```sql
ALTER TABLE evaluations
  ADD COLUMN evaluatee_dept_code        text,
  ADD COLUMN evaluatee_org_corporation  text,
  ADD COLUMN evaluatee_org_division     text,
  ADD COLUMN evaluatee_org_department   text,
  ADD COLUMN evaluatee_org_team         text;
```

- 파일: `db_mig/add_evaluation_period_org.sql` → psql **즉시 적용**(파일만 만들면 런타임 500).
- 기존 `evaluatee_department`(text)는 유지. 백필 시 `evaluatee_org_team`(또는 부 직속이면 부)으로 동기화 검토.

## 8. 백필 스크립트

- `db_mig/backfill_period_org.cjs` (멱등·`DRY_RUN` 기본).
- 흐름: 평가 로드 → `(evaluatee, evaluator, period)` 로 소스 매칭 → §4/§5 규칙으로 org 도출 → `UPDATE evaluations`.
- **DRY_RUN 산출 통계**(승인 자료): 연도별 ①~④ 분포·미지정 건수, 법인/본부/부/팀 분포, **직원33·25년 연결회계팀 검증**, 모호 케이스 목록(csv).

## 9. 프런트엔드 변경 (그룹핑 전환)

- 타입/서비스: 평가 타입에 `evaluatee_org_*` 추가, 서비스 SELECT·매핑 반영(`src/types/`, `src/lib/services/`).
- 그룹핑 전환 `employee.org_*` → `evaluation.evaluatee_org_*`:
  - `src/pages/hr/Home.tsx` (전사현황 부서별 인원)
  - `src/pages/hr/HrDepartmentsPage.tsx` (resolveGroup)
  - `OrgFilterBar`/`matchesOrgNodes` 필터도 평가 기준
- **폴백**: 평가 org가 null이면 `employee.org_*` 또는 `미지정`.
- 팀 화면(홈·피드백·일정)은 이미 평가자 기준 로스터라 영향 적음 — 확인만.
