## 0. 제도 전제 (설계의 토대 — 반드시 먼저 읽을 것)

이 설계의 모든 판단은 아래 제도 특성에 종속된다. 전제가 바뀌면 설계도 재검토.

- **절대평가** — 달성 판정이 점수 자체가 아니라 `점수 − 성장레벨` 갭으로 결정된다.
  - 초과: 점수 > 성장레벨 / 충족: 점수 = 성장레벨 / 근접: 성장레벨 − 1 / 미달: 성장레벨 − 2 이하
  - ∴ 같은 4점이라도 Lv.2면 +2 초과, Lv.4면 충족 — **원점수 분포 비교는 무의미**하다.
- **1:1 배정** — 피평가자 1명당 평가자 1명. 같은 사람을 두 평가자가 동시에 보지 않는다.
  - ∴ 단일 주기 데이터만으로는 "평가자 관대도(레벨 효과)"와 "팀 실제 실력"을 통계적으로 분리할 수 없다.
- **2년치 데이터 확보** — 2025년 1월부터 동일 채점 모델(성장레벨·점수·갭)로 평가 진행. 2026 진행 중, Q3경 활용 예정.
  - ∴ 2025(완결)을 안정 기준선, 2026(진행중)을 잠정치로 다룬다.
  - ∴ 종단 비교(전년 드리프트·전보 코호트)가 1주기부터 작동한다.
- **폐기된 발상** — 상대평가식 "강제분포 / 4점 비율 과다 플래그 / 관대도 단순 줄세우기"는 이 제도와 충돌하므로 채택하지 않는다.

## 1. 메뉴 정보구조(IA) 재편

현재 8개 평면 메뉴(전사현황·평가기간·부서별진행·평가매트릭스·사용자관리·변경요청승인·AI프롬프트·시스템설정)는 모니터링·운영액션·마스터설정이 한 줄에 섞여 있다. 성격별 3그룹으로 묶는다.

| 그룹 | 성격 | 포함(기존 + 신규) |
|---|---|---|
| **현황·분석** | 보기 | 전사 현황, 부서별 진행, 직종 벤치마크[신규] |
| **운영** | 주기 중 행동 | 변경요청 승인, 독려·리마인드 센터[신규], 일괄 공지·FAQ 푸시[신규] |
| **품질** | 공정성 점검 | 평가 품질 점검[신규] (AI 검수·표절·정합성 탭 흡수) |
| **결과** | 주기 종료 후 | 개인 피드백 리포트[신규], 부서/본부 결과 리포트[신규], 결과 확정·공개[후속] |
| **설정** | 주기 전 세팅 | 평가기간, 평가 매트릭스, 사용자·조직, 시각적 매칭 보드[신규], 시스템 설정 |

### 시스템 설정 페이지 분해 (현재 잡화점 상태)

현재 한 페이지에 평가기간 요약 / 알림 / 데이터 내보내기 / 위험영역이 스크롤로 쌓임. 상단 탭으로 분리:

- **일반** — 전사 공통값
- **알림** — 기존 NotificationSettings
- **권한·역할** — 지금 사용자 관리에 흩어진 역할 정의를 한 곳으로 (설정 부제엔 "권한"이 적혀 있으나 실제 UI 부재)
- **고급/시스템** — 위험영역, 감사로그

정리 원칙:
- **"활성 평가기간 요약" 삭제** — 평가기간 관리 페이지와 100% 중복. 필요 시 링크 한 줄.
- **"위험 영역 DB 일괄삭제" 격리** — 테스트용 기능이 운영 화면에 빨간 버튼으로 노출됨(불필요·사고위험). 권장: 환경변수(`VITE_ENABLE_DANGER_ZONE`)로 운영 빌드에서 숨김. 차선: 고급 탭 격리 + super-admin 전용.
- **흩어진 내보내기 통합** — 전사현황 "평가데이터" + 설정 "AI 문의 이력" + 부서별 export를 "리포트·내보내기" 한 곳으로.

## 2. 핵심 신규 화면 — 평가 품질 점검 (진단)

> 1:1·절대평가 제도에서 HR이 공정성을 점검하는 **HR 전용** 내부 진단. 산출물은 자동 판정이 아니라 **캘리브레이션 미팅 자료**다.

### 2.1 설계 원칙 (절대 위반 금지)

- **판정이 아니라 맥락 제공.** 시스템이 "이 평가자는 후하다/이상이다"라고 단정하지 않는다.
- **HR 전용.** 평가자에게 노출하지 않는다 → 변별력을 노린 인위적 점수 왜곡(gaming) 차단. 접근권한은 hr 롤로 제한.
- **인원·구성 항상 병기.** 수치만 띄우지 않고 "Lv.2 6명·Lv.3 2명, +0.8" 형태.
- **소표본 회색처리.** 피평가자 5명 미만 평가자는 통계 무의미 → 비교 제외 또는 "표본 부족" 표시. (관리자급은 직속 적어 자주 해당 → 상위 조직(부·본부) 단위 집계 보기 병행)
- **색은 중립.** "위험" 단정색 금지. 종착점은 "재검토 요청" 액션.

### 2.2 신호 체계

**A. 횡단 신호 — 1:1에서도 식별 확실 (주력)**

1. **변별력 (갭 분산)** — 평가자가 전원에게 비슷한 갭을 주는지. 팀 실력과 거의 무관한 순수 평가행동. 8명 전원 "충족"은 변별 안 한 신호일 확률↑. **가장 믿을 만함.**
2. **분포 건전성** — 미달 0건, 한 갭에 몰림, 점수=성장레벨+상수 평행이동. 전형적 무변별 패턴.
3. **의견 품질 연계** — 높은 점수에 의견이 짧거나 일반론(AI 검수 비구체 플래그와 연결).

> ⚠ 2026 Q3 활용 시 위 횡단 신호는 **진행 중(미완) 데이터** 위에서 계산됨. 평가자가 쉬운 케이스만 먼저 입력했을 수 있음 → **완료된 평가건만** 대상, "완료율 N%" 완결도 병기. 안정 기준선은 2025.

**B. 종단 신호 — 레벨(관대도) 접근 (보조, caveat 필수)**

레벨 효과는 단일 주기로 식별 불가 → 시간축·자연실험으로 접근. (2년치 데이터로 1주기부터 가능)

1. **전보 코호트** — 2025 A평가자 → 2026 B평가자로 옮긴 사람들의 갭 이동. 1:1에서 "같은 사람·다른 평가자"를 시간축으로 복원하는 유일한 창. (본인 성장·직무변화 노이즈 남으므로 코호트 단위로만)
2. **전년 자기 드리프트** — 같은 평가자의 2025 대비 2026 전반 관대도 변화. (`usePriorYearRecords` 활용)
3. **코호트-잔차** — 각 피평가자에 "전사 동일 성장레벨×직종 평균 갭"을 기대값으로 깔고 실제−기대 잔차 집계. 평균갭보다 덜 오염되나 여전히 팀실력과 안 갈림 → **대화용 맥락으로만**.

**B의 업그레이드 — 기질 vs 급변 (2년치라 가능)**

- **기질**: 매년 일관되게 후함 → 그 평가자 고정 스타일, 보정 시 상수처럼.
- **급변**: 작년 평균이었는데 올해 튐 → **훨씬 actionable**. 화면 상단에 "급변" 평가자 우선 배치 → HR 대화 1순위.

**C. 무결성 — 자동 플래그 정당 (표본 무관, 1주기부터 100% 작동)**

객관적 오류라 단정 OK: 빈 평가 · 전원 동일 점수 · 가중치 합 ≠ 100 · 평가의견 미작성. 1주기 ROI의 대부분이 여기서 나옴.

### 2.3 화면 구성

- 상단: **변별력 × 분포 건전성** (1:1에서 진짜 보이는 부분을 주력으로)
- 보조 패널: 종단(전보·전년·잔차) — caveat 달아 하단
- 무결성 리스트: 별도 자동 플래그
- 평가자 행 클릭 → 그 평가자의 피평가자 전체(성장레벨·점수·갭) 드릴다운
- 우측 액션: **재검토 요청** (평가자에게 코멘트 달아 반려) → 캘리브레이션 미팅으로 연결
- ※ 처음 제안한 "관대도 사분면"은 1:1에서 오해 소지 → 주력에서 제외

## 3. 추가 채택 기능 9종 — 배치·의존성

| # | 기능 | 그룹 | 비고 |
|---|---|---|---|
| 1 | 독려·리마인드 센터 | 운영 | 미완료 평가자 리스트 + 마감 임박 자동 알림·발송 이력 |
| 2 | 일괄 공지·FAQ 푸시 | 운영 | 평가자/피평가자 안내 발송, FAQ 관리 |
| 3 | AI 검수 모니터링 | 품질(탭) | 빈 19줄 프롬프트 화면 실개발. 짧음·비구체·불일치 플래그 목록→반려 |
| 4 | 평가 의견 표절·복붙 탐지 | 품질(탭) | 한 평가자가 여러 피평가자에 동일 의견. AI 유사도 |
| 5 | 점수-의견 정서 정합성 | 품질(탭) | 4점인데 부정 톤 등. AI 감성 vs 점수 미스매치 |
| 6 | 개인 피드백 리포트 생성 | 결과 | 피평가자별 결과 1장(PDF) 자동 생성·배포 |
| 7 | 부서/본부 결과 리포트 | 결과 | 임원 보고용 요약 자동 산출 |
| 8 | 직종 벤치마크 | 현황·분석 | 같은 직종 내 분포 비교 (품질 진단 baseline과 공유) |
| 9 | 시각적 매칭 보드 | 설정 | 엑셀 매칭을 드래그형 배정 화면으로. 1:1 정합성(누락·중복·자기평가) |

**구조 권고:** 3·4·5(AI 품질 3종)는 별도 메뉴로 두지 말고 **평가 품질 점검 화면의 탭으로 흡수**한다. 메뉴 비대화 방지 + HR이 한 곳에서 처리. 3은 곧 프롬프트 화면 실개발과 동일.

### 구현 의존성 신호등 (2026-06-09 코드 확인 기준)

- 🟢 **독려·리마인드(1), 공지·FAQ(2)** — `notificationApiService`/`notificationService` 존재. 발송 채널(인앱/이메일)만 확인.
- 🟢 **AI 검수·표절·정합성(3·4·5)** — `feedbackApiService` + OpenAI 연동(`AiSummaryReportModal`, `AIFeedbackChat`) 살아 있음. AI 서비스 레이어 재사용.
- 🟢 **시각적 매칭 보드(9)** — 매칭 데이터·엑셀 업로드 인프라 존재(HrUsersPage).
- 🟡 **직종 벤치마크(8)** — `job_role`(직종) 필드 존재 → 직종 단위 가능. 단 **직군(family) 필드는 없음** → 직군 묶음 원하면 필드 추가 필요.
- 🟡 **부서/본부 리포트(7)** — 엑셀 export(`hrDataExport`) 존재. PDF 출력 원하면 라이브러리 추가.
- 🔴 **개인 피드백 리포트 PDF(6)** — jsPDF·html2canvas 등 PDF 생성 라이브러리 **부재**. 신규 의존성 또는 서버 생성 필요. **가장 무거움.**

## 4. 빌드 순서 — 2026 Q3 진행 중 활용 기준

**1차 (주기 중 즉효 · 미완 데이터로도 값 · 인프라 이미 있음):**
독려·리마인드(1) · 시각적 매칭 보드(9, 1:1 정합성) · AI 검수 모니터링(3).

**2차 (품질 심화 · 종단 데이터 본격화):**
평가 품질 점검 진단(§2) + 표절(4)·정합성(5) 탭 · 공지·FAQ(2).

**3차 (주기 종료·데이터 완결 후 의미):**
개인 리포트(6, PDF 의존성) · 부서/본부 리포트(7) · 직종 벤치마크(8).

값-대비-노력: 1차가 노력 적고 효용 큼. 개인 PDF 리포트가 제일 무거움.
